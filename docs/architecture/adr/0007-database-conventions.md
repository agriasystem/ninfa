# 0007 — Database conventions: identifiers, time, value sets, names

**Status:** accepted (Gate 1)

## Context
Gate 1 creates the first real tables. Choices made here (key type, time handling, how to store
enumerations, how constraints are named) are repeated by every later gate and are expensive to change.

## Decision
- **UUID v4 primary keys**, generated by the application and by PostgreSQL's built-in
  `gen_random_uuid()` for raw inserts. No dependency for UUID v7.
- **`timestamptz` everywhere**, sessions opened with `timezone=UTC`, so aware datetimes come back in
  UTC whatever the server setting is. Creation time is a server default; `updated_at` is set by the
  ORM on UPDATE (`onupdate=now()`), not by a trigger: raw SQL updates must set it themselves.
- **Value sets as `VARCHAR` + named `CHECK`**, mirrored by a Python `StrEnum`. PostgreSQL ENUM types
  cannot drop values and restrict `ADD VALUE` inside transactions; a CHECK changes with an ordinary
  migration (drop and recreate the constraint).
- **Explicit constraint and index names** (`pk_`, `fk_`, `uq_`, `ck_`, `ix_`), migrations written by
  hand with `op.f(...)`, and a test that compares the names with the ORM metadata (CHECK constraints
  are invisible to Alembic's autogenerate diff). Procrastinate's tables are excluded from that diff.
- **Email uniqueness without extensions**: store the normalised value, enforce normalisation with
  CHECK, use a plain `UNIQUE`.
- **Read-only ORM relationships** (`viewonly=True`): rows are written by repositories with explicit
  ids, so assigning an object of another tenant to a relationship cannot silently rewrite a tenant
  column.

## Consequences
- Uniform, predictable schema; extending a value set is a one-line migration.
- Adding a constraint means naming it in two places (model and migration); the parity test catches
  drift.
- `updated_at` is not maintained for changes made outside the ORM.
- The currency check (ISO 4217 snapshot) and the timezone check (IANA, via `tzdata`) live in the
  Pydantic layer only; the database checks their format.
